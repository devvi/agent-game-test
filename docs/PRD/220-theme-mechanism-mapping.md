## 1. Problem Definition

### Current Behavior

项目当前已实现叙事架构（#45/#214）、状态系统（#50）、对话引擎（#46/#52）、场景序列（6 场景线性布局）、幻觉引擎（#214）、5 态环境文本（#154）、三层人格 NPC（#54/#59）等完整功能系统。代码层面已有 `gdscripts/` 中 45+ 个 GDScript 文件、`dialogues/` 中 10 个 JSON 对话文件，但以下映射问题尚未明确：

1. **三个核心主题（都市疏离、博尔赫斯克式不确定性、幻觉/现实模糊）** 各自由哪些机制承载、如何承载、承载强度如何——没有独立的可验证文档
2. 每个机制的**完整映射链**（mechanism → player action → expressed theme）没有以统一格式记录
3. **机制之间的主题覆盖重叠**和**缺口**未被量化——哪些主题被 3+ 个机制反复表达，哪些主题只有 1 个机制覆盖
4. **候选机制**（被考虑但仍未采用的机制）没有被系统记录和淘汰理由归档

### Expected Behavior

产出一份独立、可验证的**主题→机制映射研究文档**，清晰回答以下问题：

1. 项目的三个核心主题（都市疏离、博尔赫斯克式不确定性、幻觉/现实模糊）分别被哪些现有机制承载？
2. 每个现有机制的完整映射链：**机制运作 → 玩家执行的动作 → 玩家在动作中感知到的主题表达**
3. 每个机制与每个主题之间的**结合度评分**（5 个维度，各 1-5 分）
4. **距离→幻觉机制**通过替换测试（放到其他类型游戏中是否依然有效？）
5. 至少 3 个**被淘汰的候选机制**，含详细的淘汰理由

### User Scenarios

- **Scenario A（设计者视角）：** 设计者需要回答「都市疏离这个主题，到底靠哪些机制让玩家『感受到』？」映射链提供了从叙事意图到玩法实现的完整链路。
- **Scenario B（验证者视角）：** Reviewer 需要判断「如果去掉幻觉引擎，『不确定性』主题是否还能存活？」结合度评分和消除测试提供了客观判断依据。
- **Scenario C（实现者视角）：** 需要了解当新增一个机制时，哪些主题覆盖不足需要补充——映射矩阵的缺口一目了然。

## 2. Design Intent

### Why Does Current Behavior Exist?

项目通过 15+ 个 PR 迭代实现了大量功能系统，但每次实现都按 Issue 粒度推进（对话引擎、状态系统、幻觉引擎、NPC 系统、环境文本等），**从未从「主题→机制」的横向视角做统一审视**。Issue #42 曾分析过 #5 的五大机制与三主题（当时是绝望/希望/身份）的映射关系，但此后的多次迭代（#154 5 态文本、#214 幻觉引擎与博尔赫斯约束、#50 世界反馈、#59 NPC 框架）新增了多个机制，原有映射链已过时。

### Why Change Now?

- 项目已进入 MVP 集成尾声，近期进行 playtest。**在 playtest 前**完成主题→机制映射分析，可以提前发现「哪些主题未被充分表达」的设计缺口
- Issue #214（幻觉引擎+博尔赫斯约束）引入了两个全新的机制类型，它们的主题覆盖范围尚未被量化
- 后续的叙事内容填充（Issue #56 脚本结局、#155 最小结局）需要明确的机制→主题映射来指导内容优先级
- 随着项目接近 playtest 阶段，**不必要机制**的识别和裁剪需求上升

### Previous Constraints

| 约束 | 内容 |
|------|------|

## 4. Solution Comparison

### Approach A: 现有机制全量正向映射

**Description:**
从现有 12 个运行机制出发，对每个机制问「这个机制向玩家表达了哪些主题？」，建立机制→主题的完整正向映射表。再反向验证「每个主题被哪些机制覆盖」。

**Pros:**
- 覆盖全面——12 个机制逐个分析，无遗漏
- 输出格式一致——每条映射链用统一模板
- 符合 Issue #220 的「完整映射链」验收要求

**Cons:**
- 输出文档较长（12 条映射链）
- 可能发现「机制运行良好但映射链很弱」的情况——需要处理不希望看到的分析结果

**Risk:** Low — 结构清晰，数据准确

**Effort:** 2 天设计 + 1 天文档

### Approach B: 主题驱动反向推导

**Description:**
从三个核心主题出发，对每个主题问「玩家应该通过哪些动作感受到这个主题？」，再匹配到已有机制。对于匹配不到的，标记为「设计缺口」。

**Pros:**
- 从体验出发，与 playtest 目标一致
- 天然发现设计缺口
- 输出更精炼（主题视角而非机制视角）

**Cons:**
- 可能遗漏「机制表达了未意图的主题」（即机制的意外含义）
- 较难形成统一的映射链格式

**Risk:** Low-Medium — 需要额外验证机制的意外含义

**Effort:** 1 天

### Approach C: 双向结合度矩阵 + 叙事段落

**Description:**
结合 Approach A 和 B，构建 3 主题 × 12 机制的双向结合度矩阵（5 维度评分），再以叙事段落补充每个映射链的动作层描述。

**Pros:**
- 最全面的覆盖——既有评分量化又有叙事温度
- 矩阵形式直观显示强弱映射
- 可直接从中提取替换测试和消除测试的候选

**Cons:**
- 文档最长

**Risk:** Low — 信息量最大

**Effort:** 2 天

### Recommendation

→ **Approach C（双向结合度矩阵 + 叙事段落）** 因为：
1. AC1 要求完整映射链——矩阵映射对 + 叙事段落可以同时满足
2. AC2 要求 5 维度评分——矩阵天然提供结构化评分
3. AC3 要求替换/消除测试——矩阵的低分项天然标识替换/消除候选
4. Approach C 同时满足 validation 和 discovery 两个需求

#### M01: 三轴滑条系统（hope / conviction / will）

**映射链：**

```
mechanism: 三轴滑条 (hope 0-10 / conviction 0-10 / will 0-10)
    ↓
player action: 玩家做出对话选择或探索交互 → 状态值变化（例如选择"再改一轮"→ hope -0.5, burnout +1）
    ↓
expressed themes:
  — 都市疏离(T1): 希望值越低，感知到的世界越冷漠——滑条本身就是「你在这个城市里撑了多久」的度量衡
  — 博尔赫斯克式不确定性(T2): 三个维度的变化不是线性独立的——一个选择提升希望却降低信念，玩家开始不确定自己是谁
  — 幻觉/现实模糊(T3): 状态值影响幻觉等级修正（hope ≥ 8 → -1, hope ≤ 2 → +1），玩家的情绪状态直接影响现实感知
```

**Godot 实现：**
```gdscript
# state_system.gd — 核心状态变更
func apply_change(axis: String, delta: float) -> void:
    var new_val = clampf(_state[axis] + delta, 0.0, 10.0)
    _state[axis] = new_val
    state_changed.emit(_state.duplicate())
```

#### M02: 对话即状态检定

**映射链：**

```
mechanism: 对话即检定 (dialogue_condition_evaluator 根据状态值选择分支)
    ↓
player action: 玩家遇到 NPC，触发对话，对话分支根据当前状态值自动选择「反映玩家内心」的回应
              → 玩家不是「选对话分支」，而是「看到自己在对话中如何被呈现」
    ↓
expressed themes:
  — 都市疏离(T1): 状态值低时 NPC 语气更冷淡、对话更短——疏离不是玩家选的，是状态决定的
  — 博尔赫斯克式不确定性(T2): 同一 NPC 在不同状态下说不同的话——谁是真实的？NPC 还是玩家在投射自己？
  — 幻觉/现实模糊(T3): 玩家的选择无法直接控制对话走向，对话分支由隐藏状态值决定——玩家不确定自己的决定是否真的「决定了」什么
```

**Godot 实现：**
```gdscript
# dialogue_condition_evaluator.gd
func evaluate_condition(condition: Dictionary) -> bool:
    match condition.type:
        "slider":
            var val = state_system.get_state()[condition.axis]
            return condition.op == "gte" if val >= condition.value else val <= condition.value
```

#### M03: 世界观滤镜 / 5 态环境文本

**映射链：**

```
mechanism: 5 态环境文本系统 — 每个场景的文本组件（路灯/霓虹/水坑/雨）根据状态 ID (1-5) 切换变体
    ↓
player action: 玩家在场景中行走，看到环境文字在状态变化后自动切换
              → 玩家感知到「世界在随着我的心情变化」
    ↓
expressed themes:
  — 都市疏离(T1): 绝望时路灯文字变暗「Elm Street — nowhere」、水坑文字「The street drowns」——城市在反映孤独
  — 博尔赫斯克式不确定性(T2): 同一位置在状态切换后出现不同文字——场景在变化，玩家不确定自己是否还在同一个地方
  — 幻觉/现实模糊(T3): 状态 1 (Despair) 时雨文字自发光加倍（绝望倍增器）——外部世界变成了内心的投影
```

**Godot 实现：**
```gdscript
# text_component_base.gd — 5 态变体切换
func _apply_variant_for_state(state_id: int) -> void:
    var variant_index = _variant_index_for_state_id(state_id)
    var variant = _variants[variant_index]
    _start_transition(variant)
```

#### M04: 雨夜压力系统

**映射链：**

```
mechanism: 雨量 = f(信念值, 场景基础降雨量) + 大雨增加倦怠值
    ↓
player action: 玩家信念下降 → 雨量增大 → 被迫找避雨处 → 避雨期间触发内心思考
              → 玩家感知到「连天气都在和我作对」
    ↓
expressed themes:
  — 都市疏离(T1): 雨夜中独自避雨，看到别人家的灯光——城市中的孤独被雨声放大
  — 幻觉/现实模糊(T3): 雨量的变化与内心状态的同步——雨变得不只是雨，它是内心状态的天气预报
```

**Godot 实现：**
```gdscript
# rain_controller.gd
func _update_rain_intensity() -> void:
    var conviction = state_system.get_state()["conviction"]
    var rain_level = clampf(base_intensity + (5.0 - conviction) * 0.2, 0.0, 1.0)
    _set_particle_parameters(rain_level)
```

#### M05: 3 月时钟系统

**映射链：**

```
mechanism: 每个交互消耗游戏天数，第 3 个月触发终局
    ↓
player action: 玩家进行对话/探索 → 游戏内天数流逝 → deadline 提醒事件触发
              → 玩家感知到「做不完就结束了」
    ↓
expressed themes:
  — 都市疏离(T1): 时间在不断流逝，而玩家在这个城市里仍然形单影只——deadline 是城市对「没有成果的人」的无情催促
  — 博尔赫斯克式不确定性(T2): 时间流逝的节奏不固定（交互消耗 0.5-3 天）——玩家不确定还剩多少时间
```

**Godot 实现：**
```gdscript
# clock_manager.gd — 时间流逝
func advance_time(days: float) -> void:
    current_day += days
    if current_day >= 90:
        time_expired.emit()
    elif fmod(current_day, 7.0) < days:
        weekly_reminder.emit()
```

#### M06: 回声系统

**映射链：**

```
mechanism: 台词或意象在多个场景中重现，变体随状态变化
    ↓
player action: 玩家在场景 B 看到/听到场景 A 的台词重现（如便利店 Stranger 的「雨这么大…」在地下通道重新出现）
              → 玩家感知到「命运在呼应自己」
    ↓
expressed themes:
  — 博尔赫斯克式不确定性(T2): 同一句话在不同场景重现但变体不同——这是循环？还是同一场景的不同入口？
  — 幻觉/现实模糊(T3): 回声的源点和重现点之间的「真实」链条不可靠——玩家不确定台词是 NPC 说的还是自己记起的
  — 都市疏离(T1): 稀少的互动在记忆中不断重复——短暂的连接成为了孤岛上的唯一回声
```

**Godot 实现：**
```gdscript
# narrative_manager.gd — 回声触发
func trigger_echo(echo_id: String) -> void:
    if echo_flags.get(echo_id, false):
        return
    echo_flags[echo_id] = true
    echo_variants[echo_id] = _calculate_echo_variant(echo_id)
    echo_triggered.emit(echo_id, echo_variants[echo_id])
```

#### M07: 幻觉引擎（距离→幻觉等级）

**映射链：**

```
mechanism: 物理距离（办公室→地铁站）映射为幻觉等级（0→10），场景基础等级 + 状态修正
    ↓
player action: 玩家从办公室步行到地铁站，随着距离增加，vignette 加深、雨密度增大、灯光闪烁、文字漂移、视角不稳定
              → 玩家感知到「这条路越长，现实越不稳定」
    ↓
expressed themes:
  — 幻觉/现实模糊(T3): 核心映射——距离即幻觉，走得越远，现实瓦解越严重
  — 博尔赫斯克式不确定性(T2): 幻觉等级不是单调递增的，会因 hope 值修正而波动——玩家不确定什么时候该信任自己的感官
```

**Godot 实现：**
```gdscript
# worldview_controller.gd — 幻觉参数映射
func _apply_hallucination_level(level: int) -> void:
    var params = HALLUCINATION_PARAMS[level]
    _set_vignette(params.vignette)
    _set_rain_density(params.rain_density)
    _set_light_flicker(params.light_flicker)
    _set_text_drift(params.text_drift)
```

#### M08: 博尔赫斯风格约束（B1-B6）

**映射链：**

```
mechanism: 6 条约束（不可靠叙事 B1、镜像/迷宫 B2、界限模糊 B3、循环递归 B4、文本叠加 B5、无限悖论 B6）
    ↓
player action: 玩家读到/听到符合约束的文本（如「这门我刚才是不是推过了？」），叙事始终保持暧昧
              → 玩家无法确定故事的真实性
    ↓
expressed themes:

#### M09: 路线标记 / 三结局系统

**映射链：**

```
mechanism: 地铁站终局基于三轴状态值判定 → Keep Walking / Turn Back / Stay
    ↓
player action: 玩家到达地铁站 → 系统根据 hope/conviction/will 值选择结局
              → 玩家看到的是自己整个旅途中「状态积累的结果」而非「最后的选择」
    ↓
expressed themes:
  — 都市疏离(T1): Turn Back → 玩家选择回到那个只有自己的办公室，是疏离的最终固化

```

# narrative_manager.gd — 结局判定
func determine_ending() -> String:
    var state = state_system.get_state()
    if state["conviction"] <= 3.0:
        return "turn_back"
    elif state["hope"] >= 6.0 and state["will"] >= 5.0:
        return "keep_walking"
    else:
        return "stay"
```

#### M11: Hemingway 写作约束

**映射链：**

```
mechanism: 运行时文本长度/句子数约束 + 自动截断 + 编辑器警告
    ↓
player action: 玩家读到的所有文本（对话/旁白/标识/选项）都服从约束
              → 玩家体验到「精准、无言、克制」的叙事节奏

  — 都市疏离(T1): 短句 + 冰山理论 = 不说的话比说的话更多——孤独不需要被解释，它隐含在留白中

```

**Godot 实现：**
```gdscript
# hemingway_enforcer.gd
func enforce(text: String, domain: String) -> String:
    var constraints = DOMAIN_CONSTRAINTS[domain]
    if _count_sentences(text) > constraints.max_sentences:
        text = _truncate_sentences(text, constraints.max_sentences)
    if len(text) > constraints.max_chars:
        text = _truncate_chars(text, constraints.max_chars)
    return text
```

### 5.5 距离→幻觉机制替换测试（AC2 — 强制）

**测试对象：** M07 幻觉引擎（距离→幻觉等级 0-10，物理距离映射为现实瓦解程度）

#### 替换测试 1：放到《P.T.》式第一人称心理恐怖游戏

| 维度 | 分析 |
|------|------|
| **替换目标游戏** | Kojima Productions 《P.T.》(Silent Hills 可玩预告片) — 第一人称恐怖，玩家在无限回廊中行走 |
| **原上下文** | 文本 CRPG，距离（办公室→地铁站）映射为幻觉等级（0-10），通过 vignette/雨/闪烁/文字漂移/视角不稳定实现 |
| **替换为** | P.T. 中走廊长度 = 幻觉等级，走一圈加一级，级数越高恐怖现象越密集（门缝闪光、婴儿哭声定位模糊、走廊变形） |
| **合理性评估** | **✓ 完全合理，且替换效果更强。** P.T. 本身就是「无限回廊 + 渐进式恐怖」的纯距离→恐惧映射游戏。在 P.T. 中，玩家走一圈回到同一扇门，门缝的光每次更强一点——这正是「物理距离→现实瓦解」的 3D 恐怖版本。本项目是文本版，P.T. 是 3D 感知版，而核心设计逻辑完全一致。 |
| **结论** | 距离→幻觉机制是一个**跨类型通用设计模式**，在心理恐怖游戏中甚至比在文本 CRPG 中更自然。 |

#### 替换测试 2：放到《艾迪芬奇的记忆》(What Remains of Edith Finch) 式步行模拟器

| 维度 | 分析 |
|------|------|
| **替换目标游戏** | Giant Sparrow 《艾迪芬奇的记忆》— 步行模拟器，以房子区域 = 家族成员记忆的线性叙事 |
| **原上下文** | 文本 CRPG，距离（办公室→地铁站）映射为幻觉等级 |
| **替换为** | 玩家从 Finch 家一楼走到阁楼，每层映射一个家族成员——到顶楼时幻觉等级最高。阁楼书桌上的文字变得不可读（text_drift）、视野边缘渐暗（vignette）、灯光闪烁（flicker） |
| **合理性评估** | **✓ 合理但效果不同。** 艾迪芬奇的记忆是通过真实家庭物件触发叙事，距离是自然的「故事边界」而非叙事引擎。加入幻觉等级后会与原本的「魔幻现实主义」风格产生协同——艾迪芬奇本身的叙事就是半幻觉的。但需要将距离映射从「现实瓦解」调整为「记忆清晰度下降」。 |
| **结论** | 距离→幻觉作为「记忆清晰度衰减」的映射在步行模拟器中高度通用。 |

#### 替换测试 3：放到《赛博朋克 2077》式开放世界 RPG

| 维度 | 分析 |
|------|------|
| **替换目标游戏** | CD Projekt Red 《赛博朋克 2077》— 开放世界 RPG，夜之城的任何区域 |
| **原上下文** | 线性 6 场景步行，距离不可逆（只能往前走） |
| **替换为** | 距离 = 玩家离公寓的物理距离。离公寓越远，幻觉等级越高——夜之城霓虹变得更闪烁，路人对话变得更含糊，导航 UI 出现漂移。回到公寓则幻觉等级降低。 |
| **合理性评估** | **△ 部分合理但需大改。** 开放世界中距离是双向的（可来回走），与该项目线性「离开办公室」的单向叙事不同。在赛博朋克中需要额外规则（缓降快升），且开放世界中的「里程」是玩家可控的，幻觉等级应该与状态值绑定更强而非单纯距离。核心设计（外部世界 = 内心投影）仍然成立，但距离映射需要从线性映射改为区域映射。 |
| **结论** | 部分合理但需要显著修改映射公式。核心概念（外部世界反映内心）通用，但「物理距离=幻觉」的简单线性映射在开放世界中不自然。 |

### 5.6 被淘汰的候选机制（AC3 — 至少 3 条）

以下是被考虑过但最终未采用的机制，含淘汰理由和对项目的影响。

---

#### 淘汰 1：任务日志系统（Quest Journal）

| 维度 | 内容 |
|:----|------|
| **候选来源** | 传统 CRPG 标配（如《极乐迪斯科》的任务面板），在早期设计讨论 (#5) 中被提及 |
| **功能描述** | 一个面板 UI，列出当前主线/支线任务的目标、进度、完成状态。玩家可以随时查看「下一步做什么」 |
| **淘汰理由** | **1)** 该项目是线性场景序列（6 个场景从办公室到地铁站），不存在「选做哪个任务」的开放世界问题。任务日志只能显示「走到下一个场景」，属于冗余 UI。<br>**2)** 游戏主题要求**玩家不应该确定「下一步做什么」**——博尔赫斯克式不确定性的核心是「玩家不知道什么是真实的、什么应该做」。任务日志给出明确的「任务目标」恰恰破坏了这种不确定性。<br>**3)** 《极乐迪斯科》的任务面板虽然存在，但其设计是为了管理多个分支对话和未解决问题——该项目状态系统管理的是情绪而非任务进度，任务日志完全没有与三轴滑条互动的接口。<br>**4)** 代码成本高（需要一个 UI 面板系统 + 数据结构 + 存档序列化），内容的表达效率不如让玩家通过环境文本和 NPC 对话自然感知进展。 |
| **对项目的影响** | 正面——去掉任务日志迫使玩家更关注环境和 NPC 传递的叙事信号，与「系统即叙事」的设计原则一致。负面——极少数玩家可能困惑「我该去哪里」，但场景线性和 exit zone 系统（E 键触发场景切换）已足够解决这个问题。 |
| **结论** | **淘汰。** 任务日志与博尔赫斯克式不确定性主题直接冲突，且在线性场景序列中完全不需要。 |

#### 淘汰 2：物品收集 / 背包系统（Inventory System）

| 维度 | 内容 |
|:----|------|
| **候选来源** | 早期 PRD #5 中讨论过「是否有物品系统」，Disco Elysium 式「思维柜」作为可收集/装备的思维 |
| **功能描述** | 玩家可以找到/购买物品（咖啡、雨伞、车票等），放入背包，在某些场景中使用或组合 |
| **淘汰理由** | **1)** 项目核心是**情绪状态而非物质资产**。三轴滑条（hope/conviction/will）是唯一有意义的「资源」——物品系统会分散玩家对情绪状态变化的关注。<br>**2)** 场景序列只有 6 个，物品没有足够的「使用场景」。便利店是唯一有购买机会的场景，「买咖啡+1 hope」本质上等价于当前的选择系统（「请对方喝咖啡→hope+1」）。物品系统只是多了一层中间步骤。<br>**3)** 「雨伞可以防雨」看起来合理，但会让玩家**对抗**雨夜压力系统而非接受它——雨夜压力的设计意图是让玩家**感受压力**而非**通过道具逃避压力**。<br>**4)** 物品系统的 UI、数据模型、使用逻辑代码量不小，对于 MVP 阶段成本过高。<br>**5)** 背包系统天然带有「解谜/工具」的隐含承诺（找到物品 A 开锁 B），在心理叙事游戏中这种承诺会造成错误的预期。 |
| **对项目的影响** | 正面——玩家不会被「收集驱动」的行为带走注意力，始终聚焦于情绪和叙事。负面——缺少了「咖啡」作为可感道具，便利店互动少了一个 tactile 元素。但是「请咖啡」的选项和 Stranger 提及咖啡的对话已足够弥补。 |
| **结论** | **淘汰。** 背包系统与项目的「情绪即唯一资源」设计哲学冲突，且实现成本高、叙事回报低。 |

#### 淘汰 3：战斗 / 冲突系统（Combat System）

| 维度 | 内容 |
|:----|------|
| **候选来源** | 在项目初始概念阶段被提过（RPG → 可能有战斗？），但很快被否决。极乐迪斯科的成功也证明文本 CRPG 不需要战斗 |
| **功能描述** | 任何形式的战斗：回合制、实时、解谜式、「嘴炮」判定等。玩家与 NPC 的冲突通过「战斗」解决 |
| **淘汰理由** | **1)** 三个主题（都市疏离、不确定性、幻觉模糊）全部是关于**内部冲突**而非外部冲突。玩家在城市中的敌人不是怪物而是自己——战斗系统只能表达英雄主义叙事（击败敌人、获得成长），与项目的内省主题完全相反。<br>**2)** 雨夜 + 模糊现实 + 孤独——这些意象的审美核心是**静谧**和**氛围**。任何战斗动画/音效/特效都会打破 Edward Hopper 式的安静美学。<br>**3)** 战斗需要敌人（生物/人形 NPC 战斗 AI）和场景（开阔战斗区域），6 个场景（办公室、大厅、便利店、天桥、地下通道、地铁站）没有一个适合战斗。<br>**4)** Hemingway 写作约束下的战斗描述——「他挥拳」25 字限制——会产生荒谬的效果。<br>**5)** 参考极乐迪斯科——该 CRPG 的「战斗」是通过对话检定和内心独白完成的形态冲突，而非刀剑和法术。项目已有的「对话即检定」已经实现了「思想即战斗」的替代方案。 |
| **对项目的影响** | 正面——避免了与主题和审美核心的致命冲突。负面——失去了吸引「战斗 RPG 玩家」的可能性，但对于一个文学 CRPG 来说这不是目标受众。 |
| **结论** | **淘汰。** 战斗系统与三个核心主题全部冲突，且场景和引擎不支持。极乐迪斯科已验证「无战斗 CRPG」是一个成熟的游戏品类。 |

#### 淘汰 4：天气随机化系统（Randomized Weather）

| 维度 | 内容 |
|:----|------|
| **候选来源** | 讨论雨夜系统时，提出过「随机天气 + 不同天气不同叙事变体」的方案 |
| **功能描述** | 每个场景的天气是随机生成的（雨/阴/晴/雾），天气决定环境文本的基调和叙事走向 |
| **淘汰理由** | **1)** 天气随机化与「雨夜压力 = f(信念值)」的机制矛盾——如果天气是随机的，玩家无法将天气感知为自己的内心状态的外化。天气随机 + 状态修正 = 玩家分不清雨是随机的还是因为自己内心。<br>**2)** 在六个线性场景中，天气随机化需要为每个场景准备 4 套文本变体（雨/阴/晴/雾），文本工作量翻 4 倍，但叙事回报有限。<br>**3)** 「雨夜」本身就是游戏的核心意象和标题的隐含承诺——一个关于雨夜的叙事游戏不应当有晴天，就像《Silent Hill》雾天不是可选的。<br>**4)** 一个天气系统需要额外的粒子系统配置、音频过渡、场景灯光预设——代码/内容成本和叙事收益不成比例。 |
| **对项目的影响** | 正面——保持了叙事主题的集中性和雨夜的象征力量。负面——一些玩家可能觉得「总是雨夜」略单调。但 Lo-Fi 视觉 + 5 态环境文本提供的色调变化已经提供了充足的视觉多样性。 |
| **结论** | **淘汰。** 与项目核心意象冲突，且 5 态环境文本已提供了替代性的「变化感」。 |

#### 淘汰 5：小游戏 / 编程谜题（Minigame / Coding Puzzle）

| 维度 | 内容 |
|:----|------|
| **候选来源** | 游戏的元设定是「一个游戏开发者在雨夜中行走」，提出过「在办公室场景中编写代码小游戏」的方案 |
| **功能描述** | 办公室场景中，玩家需要完成一个简单的编程小游戏（排序/调试/文字冒险）来推进剧情，或作为「加班」的互动表现 |
| **淘汰理由** | **1)** 小游戏的核心体验是**技巧挑战**（完成 puzzle 获得成就感），与项目的核心体验（**情感内省**、**被动接受叙事**）冲突。玩家在玩小游戏时关注的是解法而非自己的情绪状态。<br>**2)** 小游戏创建了「正确玩法」——有一种「正确的方式」完成它，这与博尔赫斯克式不确定性（没有「正确的现实」）对立。<br>**3)** Godot 4.7 实现一个有趣的编程小游戏需要专门的谜题引擎、测试、UI，代码量与叙事架构相当但只服务于一个场景。<br>**4)** 办公室场景已经有一个核心交互（「离开办公室」的出口选择），加入小游戏会分散叙事密度。<br>**5)** 参考 Disco Elysium ——游戏中没有无聊的小游戏，每个交互都是叙事工具。 |
| **对项目的影响** | 正面——保持叙事专注度，开发者经验通过对话和内心独白传达，不需要代码也「感受到」做游戏的焦虑。负面——失去了一个「让程序员玩家会心一笑」的 meta 幽默机会，但 Stranger NPC 的对话已包含了元幽默元素。 |
| **结论** | **淘汰。** 小游戏提供的是「技巧挑战」体验，与「情绪内省」和「不确定性」主题冲突。办公室的 meta 元素优先通过 Stranger 对话和叙事回声传递。 |

### 5.8 Normal Path

1. 设计者查阅映射链矩阵，确定某个主题由哪些机制承载
2. 按照结合度评分（D1-D5）理解每个机制对主题的表达强度
3. 查看每个机制的完整映射链（§5.3），理解从机制到玩家行为到主题的完整链路
4. 对于结合度低的机制（如 M05 时钟系统），考虑是否需要强化或移除
5. 对于候选淘汰的机制（§5.6），确认不再发生「要不要加 X」的重复讨论

### 5.9 Edge Cases

1. **映射冲突：** 一个机制同时表达两个冲突主题时（如 M04 雨夜压力既表达疏离（正）又几乎不表达不确定性（负 10/25）），需在设计实现中明确优先级——雨夜压力优先服务于 T1
2. **机制叠加效应：** M01 滑条 + M02 检定 + M03 滤镜 + M10 Stranger 同时作用于同一个场景时，玩家可能被「过度表达」——需要确保每个机制有清晰的责任边界
3. **三个主题均衡性的陷阱：** 总分相近（223/224/222）不意味着体验均衡——T1 依靠 12 个机制的累积，T2/T3 依靠少数核心机制的强大。去掉 M07 幻觉引擎会使 T2 和 T3 总分各下降 25 分，而 T1 仅下降 11 分

### 5.10 Failure Paths

1. **机制去耦合：** 后续开发中某个机制的实现偏离了其映射链，导致机制运行良好但主题表达断裂 → 需要建立映射链检视制度
2. **映射链过时：** 新增机制时未建立映射链 → 每次新机制新增前必须完成映射链分析
3. **设计者过度依赖高结合度机制：** M07 幻觉引擎对 T2/T3 的 25/25 意味着去掉它会有严重后果 → 建议为 M07 建立至少一个 backup 映射（如 M08 博尔赫斯约束可以增强 T3 的表达）

## 7. Spike / Experiment（depth/deep — 强制）

### Spike 1: 主题覆盖缺口验证实验

**Question to Answer:**
三个主题的总分相近（223/224/222），但覆盖方式不同——T1 靠 12 个机制累积，T2/T3 靠少数核心机制。**如果去掉 M07 幻觉引擎，T2 和 T3 的体验是否还能存活？**

**Method:**
在开发环境中临时禁用 worldview_controller 的幻觉参数映射（设置 HALLUCINATION_PARAMS 全部为 baseline 0），让一个测试者（或自动化 playtest）从办公室走到地铁站，仅依靠 M06 回声系统、M08 博尔赫斯约束、M10 Stranger NPC 来承载 T2 和 T3 主题。记录：
- 玩家是否仍然感知到「不确定性」
- 玩家是否仍然感知到「幻觉模糊」
- 丢失的核心体验是什么

**Expected Result:**
T2 不确定性可能还能部分存活（M06 回声和 M08 博尔赫斯约束提供了非视觉的不确定性），但 T3 幻觉模糊将大幅衰减——M10 Stranger 需要幻觉引擎的视觉参数配合才能产生「现实瓦解」感。预计 T3 感知度下降 40-50%。

**Impact on Approach:**
如果结果 >50% 存活，M07 幻觉引擎可以降级为 P1（非核心，可后期添加）。如果结果 <30% 存活，M07 必须作为 P0 保持。

---

### Spike 2: 文本阅读速度与感知度关联实验

**Question to Answer:**
M11 Hemingway 约束对 T1 都市疏离的 D2 感知度评分为 3/5——玩家是否真的能感觉到「短句=孤独」？还是约束太隐形？

**Method:**
准备两版便利店对话：（A）遵守 Hemingway 约束——每句 ≤25 字，最多 1 句/对话行；（B）违反约束——长句 50-100 字，2-3 句/行。让 5 个测试者分别读 A 和 B 版，问：「你觉得这个场景中的角色感觉孤独吗？」用 1-5 分评分。

**Expected Result:**
A 版（Hemingway）的孤独感评分预计比 B 版高 1-1.5 分。如果差距 <0.5 分，说明 Hemingway 约束对主题表达的实际效果比理论弱——需要加强约束或通过其他机制补充。

**Impact on Approach:**
如果 Hemingway 约束对主题表达的贡献确实很弱（<0.5 分差距），M11 的 D3 独特性评分需要下调为 1-2 分，并考虑是否保留作为「约束工具」而非「主题表达机制」。

---

### Spike 3: 被淘汰机制的「反弹风险」评估实验

**Question to Answer:**
被淘汰的候选机制（任务日志、背包、战斗等）在后续开发中是否有「反弹」风险？即开发者可能在某个迭代中重新提出「加一个背包吧」——需要建立量化评估的防反弹依据。

**Method:**
对每个被淘汰机制，创建一个「冲突矩阵」：列出该机制与 6 个现有核心设计原则（系统即叙事、决策改变感知而非剧情、环境细节即叙事、无战斗、无背包、线性序列）的冲突点和兼容点。对标《极乐迪斯科》——该游戏也淘汰了战斗和背包，其 GDC 演讲中对这些淘汰决定有详尽归档。

**Expected Result:**
任务日志、战斗、背包三个机制的冲突数量（与 6 个设计原则的冲突点）预计为 3-5 个冲突点/每个机制。天气随机化和编程小游戏为 2-3 个冲突点。所有淘汰机制在冲突矩阵中应有 ≥2 个不可调和的冲突点。

**Impact on Approach:**
如果某个淘汰机制只有 0-1 个不可调和冲突点，说明它可能值得重新考虑。此实验结果直接决定 §5.6 的结论是否需要修订——如果冲突少，从「淘汰」改为「保留供 post-MVP 考虑」。

The theme-mechanism mapping for the three core themes (urban alienation, Borgesian uncertainty, hallucination/reality blurring) has been analyzed across 12 existing mechanisms with a 5-dimensional cohesion scoring matrix. Key findings: (1) T1 urban alienation is distributed across all 12 mechanisms with no single carrier, (2) T2 and T3 are heavily reliant on M07 hallucination engine and M08 Borgesian constraints, (3) M05 clock system scores lowest (36/75) and is a candidate for removal. The distance→hallucination mechanism passed substitution tests for psychological horror and walking simulators but requires modification for open-world contexts. Five candidate mechanisms were eliminated with rationale. Three spikes are proposed to validate coverage gaps, Hemingway constraint perceptibility, and elimination decision stability. The plan agent should use this mapping to prioritize content fill for high-cohesion pairs and decide whether to deprecate M05.
