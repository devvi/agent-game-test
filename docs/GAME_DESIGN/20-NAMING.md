# 20 — Naming

> 命名档案（草稿态单一事实源）：`docs/NAMING.md`。本 GDD 章节记录**持久设计决策**（约束、数据流、审美锚点），不记录命名过程值（候选名草稿见 NAMING.md，正式定稿后按需在本章补充定稿值）。
> 来源：Issue #378（B2 命名/文案，人机共做 v4 taste-draft，2026-08-11）。

## 1. 命名约束（红线，PRD §5 边界 3）

| 约束 | 值 | 理由 |
|------|-----|------|
| 词数 | 主标题 ≤ 3 词 | 1280×720 屏显 + 街机利落感 |
| 字符数 | 主标题 ≤ 12 字符 | 商店页/标题屏可读性 |
| 生僻词 | 禁止 | 第一眼秒懂优先 |
| 语言 | 主标题英文为主，中文仅作副标题候补 | 全英文 UI 语境（YOU WIN! / AI WINS! / SPACE） |
| 原创性对冲 | 含 "PONG" 的候选：副标题不得缺失或空泛 | 避免"怀旧克隆"标签，副标题承担原创性表达 |

## 2. 命名数据流（草稿 → 定稿）

```
PRD §4.2 候选名集合（5 候选 × 2-3 副标题候补 × 为什么 × 情感断言）
    │
    ▼
docs/NAMING.md（# DRAFT 草稿表 + 语境注释 + 定稿占位）← 命名档案单一事实源
    │  review 定稿就绪检查 → merge（草稿不关闭 Issue）
    ▼
用户定稿（status/human-review 队列）：选名/微调
    │
    ├─→ 替换 mini-pong/project.godot config/name + ui_start_menu.tscn TitleLabel
    ├─→ close Issue #378
    └─→ 定稿差异回写 docs/TASTE.md 风格特征节（如"短、直接、霓虹词缀"）
```

## 3. 审美坐标锚点（情感断言方向）

| 坐标 | 落地来源 | 对命名的要求 |
|------|---------|-------------|
| 霓虹赛博 | #289（暗底 #0a0a12 + 高饱和霓虹 #4a90d9） | 名字 1 秒内建立赛博语境（词缀/协议符号） |
| 街机爽感 | #367（利落击打、直接不绕弯、可控性优先） | 情感断言用体验引擎词汇：利落/直接/爽快/带电/紧张/对决；禁用空泛形容词（好听/大气） |

**情感断言标准**：名字应让玩家第一眼感到"这是个爽快的街机游戏"，而非"这是个怀旧克隆"。
